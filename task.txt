

Техническое задание — NEON RUN: LAST SIGNAL

1. Общая информация

Рабочее название: NEON RUN: LAST SIGNAL

Жанр: вертикальный roguelite / arcade / survival

Платформа: Android

Ориентация: Portrait, 9:16

Управление: одна рука, свайпы / удержание

Основные игровые режимы:

1. Забег на 30–60 секунд.

2. Бесконечный режим.



Целевая особенность: игрок должен понимать правила за несколько секунд, начинать новый забег практически мгновенно и постоянно хотеть улучшить предыдущий результат.

2. Концепция

Игрок управляет небольшим неоновым кораблём/дроидом, который движется по бесконечному энергетическому туннелю.



Туннель постоянно генерируется.



Игрок должен:

- уклоняться от препятствий;

- собирать энергию;

- выбирать между безопасным и рискованным маршрутом;

- получать временные способности;

- переживать случайные события;

- постепенно становиться сильнее во время текущего забега.



Главная механика:

двигайся → выбирай путь → собирай энергию → получай усиление → становись быстрее/опаснее → ошибись → попробуй снова.



При смерти игрок сразу видит свой результат и кнопку «Ещё раз».

4. Управление

Основное управление:

Игрок удерживает палец на экране. Положение пальца по горизонтали определяет положение корабля.



- палец слева → корабль движется влево;

- палец справа → корабль движется вправо.



Вертикальное движение происходит автоматически.



Дополнительное действие:

Свайп вверх — рывок (Dash).



Dash позволяет:

- быстро пролететь через опасную область;

- разрушить некоторые препятствия;

- получить короткую неуязвимость.



Dash имеет cooldown.

5. Core Gameplay

Игровой экран представляет собой вертикальный поток. Корабль находится примерно в нижней трети экрана. Мир движется навстречу игроку.



На пути появляются:

- энергетические кристаллы;

- стены;

- лазеры;

- мины;

- движущиеся препятствия;

- энергетические ворота;

- бонусы;

- рискованные маршруты.

6. Энергия

Во время движения игрок собирает энергетические частицы. Энергия используется для получения временных улучшений.



Количество энергии отображается в верхней части экрана.



При достижении определённого количества энергии появляется экран выбора.

7. Выбор улучшений

Каждые примерно 10–15 секунд игрок получает выбор из трёх случайных улучшений.



Примеры:

OVERDRIVE — +20% скорость

MAGNET — автоматически притягивает энергию поблизости

PHASE — каждые 8 секунд даёт 0.5 секунды неуязвимости



Игрок выбирает только одно. После выбора игра продолжается.

8. Типы улучшений

1. Magnet — увеличивает радиус сбора энергии.

2. Shield — даёт один дополнительный удар.

3. Dash+ — уменьшает cooldown Dash.

4. Overdrive — увеличивает получаемый множитель очков.

5. Phase — периодически делает игрока неуязвимым.

6. Energy+ — увеличивает количество получаемой энергии.

7. Slow Time — при попадании в опасную зону временно замедляет игру.

8. Double Core — удваивает очки за собранные энергетические объекты.

9. Система риска

Чтобы игра не превратилась просто в «уклоняйся от препятствий», игроку предоставляется возможность рисковать.



Некоторые энергетические объекты располагаются:

- рядом с препятствиями;

- в узких проходах;

- на траектории лазеров;

- между движущимися объектами.



Чем опаснее маршрут, тем больше награда.



Игрок постоянно принимает выбор:

безопасно и мало очков

или

опасно, но большой множитель.

10. Множитель очков

В верхней части экрана отображается текущий множитель:

x1.0



Если игрок некоторое время не получает повреждений и собирает энергию, множитель увеличивается:

x1.0 → x1.5 → x2.0 → x3.0 → x5.0



Получение урона сбрасывает множитель.

11. Режим «30–60 секунд»

Основной режим MVP. Цель — продержаться 60 секунд.



0–15 секунд: простые препятствия.

15–30 секунд: больше объектов.

30–45 секунд: комбинации препятствий.

45–60 секунд: высокая скорость и сложные паттерны.



После 60 секунд: RUN COMPLETE. Игрок получает результат.

12. Уровни

Уровень — не отдельная карта. Каждый уровень представляет собой набор:

- скорости;

- типов препятствий;

- частоты появления препятствий;

- доступных усилений;

- визуальных эффектов.



Пример:

LEVEL 1 — CITY

LEVEL 2 — GRID

LEVEL 3 — CORE

LEVEL 4 — VOID



Для MVP достаточно 5 уровней.

13. Бесконечный режим

После прохождения первого этапа становится доступен Endless Mode.



В нём нет финальной точки. Игрок играет до смерти.



Основной показатель: DISTANCE.

Дополнительный показатель: SCORE.

Также отображается BEST.

14. Рекорды

Игрок постоянно видит BEST SCORE и CURRENT SCORE.



После нового рекорда показывается NEW RECORD! с крупной неоновой анимацией.



Для MVP достаточно локального рекорда, хранящегося на устройстве.

16. Возрождение

Для MVP добавить возможность один раз за забег продолжить игру.



После смерти:

CONTINUE?



Игрок может продолжить после просмотра rewarded-рекламы или отказаться и начать новый забег.



После продолжения:

- игрок появляется с небольшим запасом HP;

- множитель сбрасывается;

- несколько секунд действует Shield.

17. Реклама

В MVP использовать два типа рекламы.



Rewarded Ad:

Игрок добровольно смотрит рекламу и получает:

- продолжение после смерти;

- дополнительную награду;

- временный бонус.



Interstitial:

Показывать редко, например после нескольких завершённых забегов.

Не показывать рекламу после каждой смерти.

18. Монетизация

Основной источник: Rewarded Ads.



Дополнительно:

Remove Ads — одноразовая покупка, убирающая interstitial-рекламу. Rewarded-реклама остаётся добровольной.

19. Локальная прогрессия

После каждого забега игрок получает Credits.



Credits используются для постоянных улучшений.



Примеры:

MAX HP: 1 → 2 → 3

DASH COOLDOWN: 10 сек → 9 сек → 8 сек

ENERGY BONUS: +0% → +5% → +10%

START SHIELD: 0 → 1 → 2 сек



Улучшения должны быть небольшими, чтобы игрок чувствовал прогресс, но игра не превращалась в pay-to-win.

20. Разделение прогрессии

Run Upgrades — действуют только во время текущего забега и исчезают после смерти.



Permanent Upgrades — сохраняются навсегда, например +5% energy gain.

21. Генерация препятствий

Уровни не должны полностью состоять из случайных объектов. Используется система заранее подготовленных паттернов.



Примеры:

Pattern 01:

|       |

|   X   |

|       |



Pattern 02:

| X     |

|       |

|     X |



Pattern 03:

| X | X |

|   |   |

| X | X |



Игра случайно выбирает допустимые паттерны. Каждый паттерн имеет параметр сложности.

22. Защита от невозможных ситуаций

Генератор никогда не должен создавать ситуацию, которую невозможно пройти.



Каждый паттерн имеет:

- минимальную ширину прохода;

- минимальное расстояние до следующего препятствия;

- требуемый уровень реакции;

- допустимую скорость игры.

23. Система сложности

Сложность увеличивается постепенно.



Увеличиваются:

- скорость;

- частота препятствий;

- количество препятствий;

- длина комбинаций;

- скорость движения объектов.



Рост сложности должен быть плавным.

24. HP

Игрок имеет 1–3 HP в зависимости от улучшений.



При столкновении:

- HP уменьшается;

- появляется короткая анимация;

- игрок получает небольшую неуязвимость.



При HP = 0: GAME OVER.

25. Визуальный стиль

Основной стиль: Cyberpunk / Neon / Dark.



Фон:

- практически чёрный;

- тёмно-синий;

- тёмно-фиолетовый.



Объекты:

- яркие неоновые линии;

- свечение;

- частицы;

- простые геометрические формы.



Для MVP предпочтительна стилизованная 2D/2.5D графика.

32. Onboarding

При первом запуске не показывать длинное обучение.



Короткий tutorial:

MOVE — игрок двигает пальцем.

AVOID — появляется препятствие.

DASH — показывается свайп вверх.



После этого tutorial заканчивается.



Целевое время обучения: не более 20–30 секунд.

33. Лор

Город погрузился в цифровую тьму после разрушения центрального энергетического ядра.



Игрок управляет последним автономным дроном.



Его задача: доставить последний энергетический импульс к ядру.



Каждый новый уровень — более глубокий сектор города.



История подаётся короткими текстами, визуальными сценами и названиями уровней.

34. Технический стек

Рекомендуемый движок: Godot 4.x.



Причины:

- бесплатный;

- open-source;

- хорошо подходит для небольшой 2D/2.5D игры;

- быстрый цикл разработки;

- простой UI;

- хорошая работа с Android;

- удобная procedural generation;

- небольшой размер проекта;

- отсутствие лицензионных платежей движка.



Для MVP Unreal Engine не использовать. Unity также подходит, но для небольшого 2D arcade/roguelite проекта Godot позволяет держать проект проще.

36. Основные игровые системы

GameManager — состояние игры, старт, пауза, завершение, перезапуск.



PlayerController — движение, Dash, HP, столкновения, Shield.



ObstacleManager — создание препятствий, удаление, паттерны.



RunManager — текущий забег, время, distance, score, multiplier.



UpgradeManager — выбор и применение улучшений.



ProgressionManager — Credits, постоянные улучшения, уровни.



SaveManager — рекорд, Credits, уровни улучшений, открытые режимы, настройки.

38. Offline

Основной gameplay должен работать без интернета.



Без интернета доступны:

- игра;

- рекорды;

- прогресс;

- upgrades;

- endless;

- настройки.



Реклама требует интернет-соединения.



Если рекламы нет, Continue становится недоступным. Игра продолжает работать нормально.

39. FPS

Целевой показатель: 60 FPS.

Минимальная цель: 30 FPS.



Игра должна корректно работать на бюджетных Android-устройствах.



Необходимо избегать большого количества одновременно существующих объектов, тяжёлых particle effects и сложных shader effects.



Для препятствий желательно использовать object pooling.

В первую версию НЕ включать:

- PvP;

- аккаунты;

- сервер;

- онлайн-рейтинг;

- multiplayer;

- сложный сюжет;

- большое количество персонажей;

- скины;

- кланы;

- социальные функции;

- сложную экономику.



MVP должен состоять из:



Gameplay:

- движение;

- препятствия;

43. Критерий готовности MVP

MVP считается готовым, если новый пользователь может:

1. Запустить игру.

2. Понять управление без инструкции.

3. Начать первый забег менее чем за 10 секунд.

4. Играть одной рукой.

5. Получать случайные улучшения.

6. Погибнуть.

7. Увидеть результат.

8. Начать новую попытку одним нажатием.

9. Получить постоянную награду.

10. Улучшить персонажа.

11. Открыть Endless.

12. Установить новый рекорд.

13. При наличии рекламы продолжить забег после смерти.

44. Главный принцип дизайна

Вся игра должна строиться вокруг короткого цикла:



PLAY → DODGE → COLLECT → UPGRADE → SURVIVE → DIE → REWARD → TRY AGAIN



Время от смерти до новой игры: не более 3–5 секунд без учёта рекламы.



Количество действий до нового забега должно быть минимальным.



Игрок не должен проходить через длинные меню, диалоги, загрузочные экраны и сложные настройки.



Основная цель MVP:

Игрок умер → увидел результат → нажал TRY AGAIN → снова играет.

45. Возможное развитие после MVP

Если базовый gameplay показывает хорошие показатели удержания, можно добавить:



Персонажей — разные дроны с небольшими особенностями.

Скины — только визуальные изменения.

Новые биомы — Cyber City, Reactor, Deep Grid, Void, Core.

Daily Challenge — уникальный забег каждый день.

Weekly Challenge — особые модификаторы.

Achievements — например Survive 60 sec, Reach x5 multiplier, Collect 1000 energy, Complete 10 runs.

47. Итоговая концепция

NEON RUN: LAST SIGNAL — мобильный вертикальный roguelite, построенный вокруг очень коротких забегов.



Игрок одной рукой управляет движением неонового дрона, уклоняется от препятствий, собирает энергию и получает случайные улучшения.



Каждый новый забег немного отличается от предыдущего.



Постоянная прогрессия позволяет становиться сильнее.



Рост сложности заставляет игрока постоянно проверять: «А смогу ли я сейчас побить свой рекорд?»



Главная механика удержания:

короткий забег + случайные улучшения + рекорд + мгновенный restart.



Главная монетизация:

добровольная rewarded-реклама за продолжение после смерти.



Технология:

Godot 4.x + Android.



MVP намеренно ограничен, чтобы сначала проверить интерес к core gameplay, а затем наращивать объём контента.
